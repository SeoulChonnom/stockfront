열린 결정 · 백엔드 의존성

  • D-01 (가정) Viewer/Operator 2단계. 역할 출처가 없어 프런트 상태로 대체 — 실제로는 권한 API 필요
  • D-05·D-06 (BACKEND) 인접 날짜 이동은 날짜 산술로 구현. 영업일·스냅샷 존재 여부는 보장되지 않아 없는 날짜는 404 상태로 안내
  • 파이프라인 단계 (PROPOSED·BACKEND) 단계별 상태·소요는 현재 API에 없음. app/batch/steps 모듈명을 근거로 가정. 미제공 시 errorCode/logSummary만 표시하도록 축소 가능
  • D-11·D-12 (Open) force·rebuildPageOnly는 고급 모드로 분리하고 확인 단계에서 경고. 권한·audit 정책은 백엔드 확인 필요
  • D-13 (Open) PARTIAL 누락 범위는 현재 문자열 partialMessage. 구조화 필드가 생기면 섹션 자동 매핑으로 대체
  • 401/403 구분 (BACKEND) 세션 만료와 권한 없음을 다른 화면으로 처리. 현재 계약은 코드 구분만 있음
  • 409 payload (BACKEND) 중복 실행 시 기존 jobId를 함께 주면 “실행 중 작업 열기”가 동작. 없으면 목록 이동으로 대체
  • 채택 jobId를 URL query로 승격(선택 deep link·Back 복원). articleLinks·metadata를 근거/신뢰 정보로 복원
